# PRD Writing

创建 PRD 骨架草稿，并通过 grill-me 逐节审查，迭代完善直至无分歧。

## 工作流

1. **创建骨架草稿**：基于 `assets/prd-template.md` 生成 PRD 骨架，结合用户提供的背景、目标用户与已有素材，填充各章节的初步内容。
2. **核心问题前置可行性分析**：在提出核心问题之前，先对候选核心问题做技术可行性分析——梳理现有技术栈与系统能力、资源与约束、关键技术风险，判断各候选问题在技术上是否可解，据此收敛候选集。分析结论写入 PRD 的「技术可行性分析」章节。
3. **逐节审查（调用 grill-me）**：对以下每个部分调用 `grill-me` skill，检查矛盾点、发掘潜在问题：
   - 背景
   - 需求（功能性需求 / 非功能性需求）
   - 名词解释
   - 核心问题
   - 技术可行性分析
   - 方案设计（须在步骤 4、5 完成后审查）
   - 模块
   - 数据流向
   - 业务规则
4. **核心问题后置可行性分析**：核心问题经 grill-me 审查确定后，针对最终确定的核心问题逐条复核技术可行性，给出明确结论（可解 / 有条件可解及前提 / 不可解及原因），更新「技术可行性分析」章节。若存在不可解项，回到核心问题修订，不得进入方案设计。
5. **确定方案与技术选型**：可行性确认通过后，再确定方案设计和技术选型。每个关键决策必须写明决策理由：为何选择该方案、替代方案的权衡分析、影响决策的约束条件；依据必须自包含于文档内，不得使用"参考 xxx"式的外部引用。
6. **迭代完善**：根据 grill-me 审查中暴露的分歧与潜在问题，更新 PRD 对应章节，再回到步骤 3 继续审查，直到所有部分无任何分歧。

## 审查要点

- 需求是否与背景呼应、无冲突
- 功能性需求与非功能性需求是否覆盖完整
- 技术可行性分析是否覆盖全部核心问题，结论是否明确且有依据
- 方案设计是否满足全部需求，是否建立在可行性结论通过的基础上
- 技术选型等关键决策是否写明决策理由（含替代方案权衡与约束条件）
- 模块划分、数据流向、业务规则是否自洽
- 名词解释是否消除了歧义

## 完成标准

- 骨架模板中所有章节均有内容
- grill-me 审查后无未解决的分歧或潜在问题
- 用户确认 PRD 定稿
