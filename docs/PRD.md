## 背景

- 公司提供了适配 Anthropic Claude Code 响应格式的 API key，该 key **仅限用于代码审查**，不能用于其他用途
- 日常开发中，开发者既需要用自己的 API key 完成常规任务（编码、对话、文档），也需要在允许的场景调用公司 key（如代码审查）
- 现有 Claude Code CLI / 官方插件使用单一配置，无法按开发阶段灵活切换不同的 API key
- 目标：构建一个 **Workflow Agent VS Code 插件**，按开发阶段组织工作流，每个阶段可独立配置不同的 API key，且与 Claude Code CLI / 官方插件**并行使用不冲突**

### 设计愿景：时间旅行（Time Travel）机制

> 本项目尚处于构想阶段（PRD 编写中），以下为希望达成的设计目标，非既有能力。

- 各阶段的对话上下文**互相独立**（隔离的），但阶段之间存在关联，用户会反复切换阶段
- 为解决"隔离但关联"的矛盾，插件在项目当前目录创建**文件系统软链接（symlink）**：
  - `docs/.workflow/` 目录下全部是软链接，每个阶段一个固定链接（如 `docs/.workflow/计划阶段`）
  - 各阶段输出物通过软链接指向项目全局目录，链接不随阶段切换而变化
- 基于 git 实现 **Time travel 工具**（愿景）：
  - 记录 **conversation transcript（对话转录）** 和 **file snapshots（文件快照）**
  - 支持对话和文件的**原子性回滚**，回到任意历史状态

## 需求

### 功能性需求

- FR1: 按开发阶段组织工作流（默认阶段：2.计划阶段、3.设计阶段、4.开发阶段、5.测试阶段）
- FR2: 每个阶段可独立配置 API key（含 baseURL、模型等）
- FR3: 在哪个阶段使用哪个 API key 由用户自由决定
- FR4: 插件与 Claude Code CLI 可同时运行，互不冲突（进程级不冲突：插件用 Agent SDK 跑独立会话，与 CLI 是两套进程/配置）
- FR5: 插件内部基于 Claude Agent SDK 实现
- FR6: 插件为**对话流（Chat Flow）UI**：用户在聊天界面中可直接切换当前阶段
- FR7: 用户通过对话流 UI 切换阶段，无需重启插件或新建会话
- FR8: 各阶段对话上下文**互相独立**（隔离），切换阶段即切换上下文
- FR9: 项目当前目录下创建**文件系统软链接**关联各阶段输出物：
  - `docs/.workflow/` 目录下全部为软链接，每阶段一个固定链接（如 `docs/.workflow/计划阶段`）
  - 链接指向项目全局目录，不随阶段切换而变化
- FR10: **API key 管理与安全需求待定**（待决策项：手动明文配置 / 系统密钥链安全存储 / 复用现有环境变量与 Claude Code 配置，需在方案阶段确定）
